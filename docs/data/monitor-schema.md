# monitor_db schema

Owner: [monitor](../services/monitor.md) (API process and worker processes). Role: `monitor_svc`.

Also contains `outbox` ([messaging tables](messaging-tables.md)). Monitor consumes no events, so it has no `processed_messages`.

## Tables

```sql
CREATE TABLE monitors (
  id                     uuid        PRIMARY KEY DEFAULT uuidv7(),
  org_id                 uuid        NOT NULL,          -- from the JWT; no FK (lives in auth_db)

  -- definition (edited by users)
  name                   text        NOT NULL CHECK (length(name) BETWEEN 1 AND 100),
  url                    text        NOT NULL CHECK (length(url) <= 2048),
  method                 text        NOT NULL DEFAULT 'GET' CHECK (method IN ('GET', 'HEAD')),
  interval_seconds       integer     NOT NULL DEFAULT 60    CHECK (interval_seconds BETWEEN 10 AND 3600),
  timeout_ms             integer     NOT NULL DEFAULT 10000 CHECK (timeout_ms BETWEEN 1000 AND 30000),
  accepted_status_codes  text        NOT NULL DEFAULT '200-299',
  failure_threshold      smallint    NOT NULL DEFAULT 3 CHECK (failure_threshold BETWEEN 1 AND 10),
  recovery_threshold     smallint    NOT NULL DEFAULT 2 CHECK (recovery_threshold BETWEEN 1 AND 10),
  paused                 boolean     NOT NULL DEFAULT false,
  definition_version     integer     NOT NULL DEFAULT 1,

  -- confirmed state (written only by workers and by pause/resume)
  status                 text        NOT NULL DEFAULT 'UNKNOWN'
                                     CHECK (status IN ('UNKNOWN', 'UP', 'DOWN', 'PAUSED')),
  state_version          integer     NOT NULL DEFAULT 0,
  consecutive_failures   smallint    NOT NULL DEFAULT 0,
  consecutive_successes  smallint    NOT NULL DEFAULT 0,
  last_checked_at        timestamptz,
  last_status_change_at  timestamptz,

  -- scheduling and lease (written only by workers)
  next_check_at          timestamptz NOT NULL DEFAULT now(),
  lease_owner            text,
  lease_expires_at       timestamptz,
  lease_token            bigint      NOT NULL DEFAULT 0,   -- fencing token

  created_at             timestamptz NOT NULL DEFAULT now(),
  updated_at             timestamptz NOT NULL DEFAULT now(),

  CONSTRAINT paused_matches_status CHECK ((status = 'PAUSED') = paused)
);

-- The claim query: due, not paused. Partial index keeps it small.
CREATE INDEX monitors_due_idx ON monitors (next_check_at) WHERE paused = false;

-- List an organization's monitors, newest first.
CREATE INDEX monitors_org_idx ON monitors (org_id, created_at DESC);

-- Names are unique within an organization, case-insensitively.
CREATE UNIQUE INDEX monitors_org_name_idx ON monitors (org_id, lower(name));

CREATE TABLE monitor_checks (
  id              uuid        PRIMARY KEY,             -- the checkId, generated by the worker
  monitor_id      uuid        NOT NULL REFERENCES monitors (id) ON DELETE CASCADE,
  checked_at      timestamptz NOT NULL,
  outcome         text        NOT NULL CHECK (outcome IN ('SUCCESS', 'FAILURE')),
  status_code     smallint,
  latency_ms      integer,
  failure_reason  text CHECK (failure_reason IN
                    ('TIMEOUT', 'DNS_ERROR', 'CONNECTION_ERROR', 'TLS_ERROR',
                     'UNEXPECTED_STATUS', 'BLOCKED_TARGET')),
  worker_id       text        NOT NULL,
  CONSTRAINT failure_has_reason CHECK ((outcome = 'FAILURE') = (failure_reason IS NOT NULL))
);

CREATE INDEX monitor_checks_monitor_idx ON monitor_checks (monitor_id, checked_at DESC);
CREATE INDEX monitor_checks_checked_at_idx ON monitor_checks (checked_at);   -- janitor
```

The database allows `interval_seconds` down to 10 for the lab; the API enforces a minimum of 30 unless `ALLOW_FAST_INTERVALS=true`.

## Design notes

**One wide row, three writers.** `monitors` holds what users edit (definition), what workers conclude (state) and what the scheduler needs (lease). Users and workers therefore update the same row. They touch different columns, and PostgreSQL row locks are held only for the duration of each short `UPDATE`, so this is safe; but a user's edit and a worker's completion can serialise behind each other briefly. Splitting scheduling into its own table is the documented first refactoring if contention appears ([ADR-0010](../adr/0010-postgres-leases-for-scheduling.md)).

**User edits never touch state or lease columns.** `PATCH /v1/monitors/{id}` runs `UPDATE … SET name = …, definition_version = definition_version + 1` with an explicit column list (never `repository.save(entity)`, which would write every column back and could overwrite a worker's concurrent update). This is the concrete reason for the "no `save()` for updates" rule in [ADR-0005](../adr/0005-typeorm-and-class-validator-usage.md).

**Hard delete.** Deleting a monitor removes the row (and its recent checks by cascade) and writes `monitor.definition.changed.v1` with `deleted: true` in the same transaction. A check that was in flight finds no row for its fencing update and is discarded.

**`lease_token` is `bigint`.** It increments on every claim: at one claim per 10 seconds a 32-bit integer would last ~680 years, but there is no reason to think about it.

## The three statements that matter

**1. Claim** (worker, every second, `$2` = free slots):

```sql
UPDATE monitors m
   SET lease_owner      = $1,
       lease_expires_at = now() + interval '60 seconds',
       lease_token      = m.lease_token + 1
 WHERE m.id IN (
         SELECT id
           FROM monitors
          WHERE paused = false
            AND next_check_at <= now()
            AND (lease_expires_at IS NULL OR lease_expires_at < now())
          ORDER BY next_check_at
          LIMIT $2
            FOR UPDATE SKIP LOCKED)
RETURNING m.id, m.org_id, m.name, m.url, m.method, m.timeout_ms, m.accepted_status_codes,
          m.interval_seconds, m.failure_threshold, m.recovery_threshold,
          m.status, m.state_version, m.consecutive_failures, m.consecutive_successes,
          m.lease_token;
```

**2. Complete** (worker, one transaction per check):

```sql
BEGIN;
UPDATE monitors
   SET status = $new_status, state_version = $new_state_version,
       consecutive_failures = $cf, consecutive_successes = $cs,
       last_checked_at = $checked_at,
       last_status_change_at = COALESCE($changed_at, last_status_change_at),
       next_check_at = now() + make_interval(secs => $next_in_seconds),
       lease_owner = NULL, lease_expires_at = NULL
 WHERE id = $id
   AND lease_token = $token;            -- fencing: 0 rows → ROLLBACK and discard
INSERT INTO monitor_checks (…) VALUES (…);
INSERT INTO outbox (routing_key, envelope, headers) VALUES ('monitor.check.completed.v1', …);
-- only if the status changed:
INSERT INTO outbox (routing_key, envelope, headers) VALUES ('monitor.state.changed.v1', …);
COMMIT;
```

`$next_in_seconds` is `interval_seconds`, or 10 (`retryIntervalSeconds`) while a status change is suspected but unconfirmed.

**3. Pause** (API): sets `paused = true`, `status = 'PAUSED'`, `state_version + 1`, resets counters, and writes `monitor.state.changed.v1` (to `PAUSED`) and `monitor.definition.changed.v1` to the outbox. Resume sets `status = 'UNKNOWN'`, `next_check_at = now()`.

## Indexes and the queries they serve

| Index | Query |
|-------|-------|
| `monitors_due_idx` (partial) | The claim query's inner `SELECT` |
| `monitors_org_idx` | `GET /v1/monitors` |
| `monitors_org_name_idx` (unique) | Duplicate-name check → `409` |
| `monitor_checks_monitor_idx` | `GET /v1/monitors/{id}/checks` |
| `monitor_checks_checked_at_idx` | Janitor |

Use `EXPLAIN (ANALYZE, BUFFERS)` on the claim query in Phase 3 and confirm it uses `monitors_due_idx`; this is a good exercise in reading a query plan.

## Events written to the outbox

| Change | Event |
|--------|-------|
| Create, edit, pause, resume, delete | `monitor.definition.changed.v1` |
| Every completed check | `monitor.check.completed.v1` |
| Confirmed status change, pause, resume | `monitor.state.changed.v1` |

## Retention

| Data | Rule |
|------|------|
| `monitor_checks` | Rows older than 24 h deleted hourly. Long-term history belongs to [analytics](analytics-schema.md) |
| `outbox` | Published rows deleted after 24 h |
